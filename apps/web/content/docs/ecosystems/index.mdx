Every ecosystem follows the same loop: inventory, next version, API diff, your lines, upgrade, verify. What differs is the tool at each step, and those tools are picked per language, not shared.

## What is the same everywhere

- **Registry data** comes from deps.dev, with the npm registry as a fallback for npm. Advisories come from OSV, cross-checked with GitHub's advisory database, plus ruby-advisory-db for gems. Every locked version is checked, direct and transitive.
- **The next version** is the newest stable release that is at least 7 days old, respects your npm overrides and resolutions, and isn't deprecated or yanked. Majors are allowed. Security fixes skip the cooldown.
- **Only majors are diffed.** A minor or patch upgrade is a plain bump that the sandbox decides.
- **Packages are read, never run.** Teire checks each tarball's integrity and unpacks it with its own extractor (links and `..` paths refused) on the worker. Your code and its dependencies install and run only in the sandbox.
- **Release notes** are read by Nemotron. Each item must quote the fetched text word for word, or it is dropped.

<Callout title="Type level or syntax level">
  Teire says **not affected** only when every use was resolved by type. Where the search is syntax-level (Cargo, RubyGems, and Maven/Gradle until the fix compiles your code), a repository that doesn't use the change reads **inconclusive**. The sandbox then decides. Across the six clean repositories in the evaluation, none was called affected.
</Callout>
