## What Teire reads

Every directory with a `package.json` and a lockfile, plus the root. Workspaces resolve per importer: pnpm importers, npm `packages`, Yarn `workspaces`, Berry `@workspace:`, Bun workspaces. It reads `dependencies`, `devDependencies`, `optionalDependencies` and `peerDependencies`, and resolves `npm:` aliases to the real package.

Your own rules hold:

- npm `overrides`, `pnpm.overrides` and Yarn `resolutions` pin a version.
- Release-age gates from pnpm `minimumReleaseAge`, `.npmrc` `min-release-age`, `.yarnrc.yml` `npmMinimalAgeGate` and `bunfig.toml` stretch the cooldown. Teire uses the longest gate that applies.
- `@types/node` never goes above your Node major (from Volta, `.nvmrc`, `.node-version` or `engines.node`).

## How breaks are found

For a major, Teire walks the package's bundled `.d.ts` files, or `@types/<name>` on the same major, or its exports when there are no types. It compares the old version with the new and records:

- removed exports and members,
- calls with too few or too many arguments,
- properties that became required,
- deep imports through `exports` that no longer resolve.

A changed type is an annotation, not a break.

Your code is then type-checked against the installed version. A site counts only where the checker resolves it to the package: a method with the same name on your own class doesn't count.

## How it upgrades

The version range in `package.json` is edited as text, keeping its style (`^`, `~`, exact). For pnpm `catalog:` entries, the edit goes into `pnpm-workspace.yaml`. Then the lockfile alone is regenerated in the sandbox:

| Manager | Command |
|---|---|
| npm | `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` |
| pnpm | `pnpm install --lockfile-only --ignore-scripts` |
| Yarn Berry | `yarn install --mode=update-lockfile` |
| Yarn v1 | `yarn install --ignore-scripts --non-interactive` |
| Bun | `bun install --lockfile-only --ignore-scripts` |

A transitive security fix first tries an in-range update (`pnpm update`, `yarn up -R`, `npm update`), then an override.

Deterministic codemods apply on npm: a removed deep import rewritten to the path the migration note names, or a renamed call, only where the target proves the new name exists.

## How it verifies

Install: `npm ci`, `pnpm install --frozen-lockfile`, `yarn install --immutable` or `--frozen-lockfile`, `bun install --frozen-lockfile`. Lifecycle scripts never run.

The checks come from your CI first: workflow steps that run a package script for typecheck, build or test. Next come your scripts (`typecheck`, `type-check`, `test`, `test:unit`…). Last come the defaults: `tsc --noEmit` when you have TypeScript and a `tsconfig.json`, then `vitest run` or `jest --ci`. Test counts come from a JSON report when the script is a plain Vitest or Jest call, otherwise from the summary line. Watch, e2e, Playwright, Cypress, lint and format scripts are skipped.

<Callout type="warn" title="Limits">
  The binary `bun.lockb` can't be read; use the text `bun.lock`. Bun and Yarn v1 have no in-range transitive update, so a transitive security fix becomes an override. Yarn and Bun installs aren't yet proven to work offline (npm and pnpm are). The sandbox runs Node 24 only.
</Callout>
