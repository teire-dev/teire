## What Teire reads

Any directory with `pyproject.toml`, a `Pipfile` or `requirements*.txt`/`.in`. That covers PEP 621 dependencies and PEP 735 groups, Poetry tables, Pipfiles, and requirements files with `-r`/`-c` includes, `--hash` lines, `-e` and URLs. Versions come only from a lockfile or an exact `==` pin; anything looser is unresolved. Environment markers are evaluated for Linux and CPython 3.12. Dev groups and `requirements-dev`/`test`/`lint` files count as development scope.

A Python helper does the reading, run in isolated mode with pinned `packaging`, `griffe` and `jedi`.

## How breaks are found

For a major, Teire downloads the wheels of both versions (sdists are never built). It checks their sha256 and has griffe compare them **without importing any code**. Removed functions, classes, parameters and attributes become breaks.

jedi then resolves your calls statically against the installed wheel, recording the keyword arguments of each call. A removed keyword argument counts only at calls that pass it.

Versions whose every file needs a newer Python than 3.12 are skipped.

## How it upgrades

| Manager | Command |
|---|---|
| uv | `uv lock --upgrade-package name==X` (the `pyproject.toml` range is edited first if it excludes X) |
| Poetry | `poetry add name==X --lock`, or `poetry update name --lock` |
| Pipenv | `pipenv upgrade name==X` |
| pip-tools | `pip-compile --upgrade-package name==X` (or `uv pip compile`) |
| pip | the pinned line edited |

Hash-pinned requirements get every target file's sha256; without them, the edit is refused. Teire never re-locks everything.

## How it verifies

Install with `uv sync --frozen --all-groups`, `poetry install --no-root`, `pipenv sync --dev`, or a fresh `.venv` from the lock. The checks are pytest, mypy and pyright (or basedpyright), taken from CI or configured in the project, and run through your own runner (`uv run --frozen --offline`, `poetry run`, `pipenv run`). pytest writes a JUnit report for exact test counts.

<Callout type="warn" title="Limits">
  The sandbox runs Python 3.12 only. A project that needs another Python is not switched. griffe can't see return or attribute type changes; release notes cover those. The agent has no version-pinned docs lookup for PyPI packages yet. Only uv installs are proven to work offline.
</Callout>
