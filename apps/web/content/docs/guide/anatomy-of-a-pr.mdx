## Title

| Change | Title |
|---|---|
| Package | `Upgrade <package> from <version> to <target>`, plus ` and adapt the code` when code changed |
| Security | `Upgrade <package> from <version> to <target> to fix <GHSA id or N advisories>` |
| One model | `Replace retired model gpt-4.1-nano with gpt-5.6-luna` (or `retiring`, before the date) |
| Several models | `Replace N retired <Provider> models` |
| Other API change | `Adapt to <change title>` |

## Body, section by section

<Steps>
<Step>

**The verdict line** comes first: **Verified.**, **Draft: typecheck only.**, **Draft: checks already failing.**, **Draft: needs live access.**, **Draft: needs a local service.**, **Draft: environment differs.**, or **Needs a human.** From the Go run:

> **Verified.** `github.com/golang-jwt/jwt/v4` v4.5.2 → github.com/golang-jwt/jwt/v5 v5.3.1, with code changes in 1 file. The repo's checks pass before and after the upgrade (4/4 tests).

</Step>
<Step>

**Why this repo** lists each line that uses what changed, linked to the exact commit, with what changed there (symbol removed, arity changed, …). The heading says how the lines were found: by type, or by name where the ecosystem's search is syntax-level.

> github.com/golang-jwt/jwt/v5 v5.3.1 removes or changes APIs this repo calls (resolved by type, not by name):

> - `auth/token.go:22` `jwt.StandardClaims` (symbol removed)
> - `auth/token.go:49` `var ve *jwt.ValidationError` (symbol removed)
> - …

Up to 12 sites per change. Lines whose types merely changed are listed as "Also used, annotated only".

</Step>
<Step>

**What changed upstream** summarises the API diff and quotes the release notes. Each quote comes word for word from a document Teire fetched:

> Comparing the public API of v4.5.2 and github.com/golang-jwt/jwt/v5 v5.3.1: removes 34 API(s); adds 6 required propert(ies) to existing types.

</Step>
<Step>

**Changes** lists each file and who changed it. Your package manager changed the manifest and lockfile; Teire changed the imports; Nemotron changed the rest. Then come the agent's own summary and the full diff in a fold:

| File | Change |
|---|---|
| `go.sum` | regenerated by go (+2/−2 lines) |
| `go.mod` | updated by go |
| `auth/token.go` | Teire: imports `github.com/golang-jwt/jwt/v4` → `github.com/golang-jwt/jwt/v5`; edited by NVIDIA Nemotron 3 Ultra |

</Step>
<Step>

**Verification** shows each check's exact command and its result on both sides:

| Check | Before (v4.5.2) | After (v5.3.1) |
|---|---|---|
| build `go build -o /dev/null ./...` | ✓ exit 0 | ✓ exit 0 |
| typecheck `go vet ./...` | ✓ exit 0 | ✓ exit 0 |
| test `go test -count=1 -json ./...` | ✓ exit 0 · 4/4 passed | ✓ exit 0 · 4/4 passed |

</Step>
<Step>

**Receipt** lists every model call with its tokens and cost, and the sandbox time:

| Step | Model | Tokens in / out | Cost |
|---|---|---|---|
| Fix attempt 1: 22 steps → verified | NVIDIA Nemotron 3 Ultra | 276.5k / 3.6k | $0.176 |
| Review of the passing diff: no problems found | NVIDIA Nemotron 3 Ultra | 1.4k / 1.1k | $0.0046 |
| Sandboxes: install + checks, both sides | Cloudflare Containers | — | 27 s |

An upgrade's first run also has a "Read the release notes" row. This run reused an earlier reading of the same notes, so it paid nothing for them.

</Step>
<Step>

**Risks not covered** lists the behaviour changes the release notes describe, each with its quote, the reasons when the evidence is not `verified`, and anything the review raised. Every package PR ends this section with "Lint, end-to-end and integration suites were not run; dependencies were installed without lifecycle scripts." Model and API PRs end with the network-off and prompt-tuning notes instead.

</Step>
<Step>

**Rollback** says how to undo it. **Commands** lists `@teire rebase · @teire recreate · @teire explain · @teire ignore <package>`. A footer links the live run and names the models used, or "deterministic fix, no model call".

</Step>
</Steps>

## Ready, draft or issue

| Evidence | Opens as | Labels |
|---|---|---|
| `verified` | a ready PR, check run **success** | `teire`, the ecosystem (`npm`, `pypi`, `go`, `cargo`, `rubygems`, `maven`) and `upgrade`, `major` or `security`. Model and API PRs get `model-retirement` or `api-change` and the provider |
| `typecheck_only` · `pre_existing_failure` · `needs_live_access` · `needs_local_service` · `environment_mismatch` | a draft PR, check run **neutral** | the same, plus the evidence, such as `typecheck-only` |
| `regression` · `unverified` · `timeout` | an issue, **Teire needs a human: …**, with the body and the reasons | `teire` |

`pullRequests.labels` in `teire.yml` adds your own labels.

## On GitHub

- **Branch.** `teire/<group>`, such as `teire/npm/openai/7.38.0` or `teire/models/openai`. Teire never commits to your default branch and never merges.
- **Commit.** One commit made through GitHub's API as the App, which GitHub signs (very large changes go through the Git Data API instead). Its headline is the PR title, after any `pullRequests.commitMessage.prefix`.
- **Check run "Teire".** On the PR's head commit, with a notice annotation on every line the change reaches. Its details link the run page.
- **Superseded.** When a PR opens for a newer target of the same package, Teire closes the older PR with "Superseded by #N".
- **Base moved.** A push to the default branch that touches dependency files rebases every open Teire PR. So does GitHub reporting a PR as no longer mergeable. A rebase reruns the fix and the verification.
- **CI failed.** If your CI fails on a Teire PR, Teire makes **one** repair attempt per commit. It reads up to 3 failing checks and the last 6,000 characters of their logs. It says so in a comment.
- **Your commits.** If someone else pushes to a Teire branch, Teire stops updating it and comments on the PR. It never overwrites your commits.
- **Closed.** Closing marks the change dismissed and merging marks it fixed. Later scans don't reopen it.

## The onboarding PR

The first scan of a repository without `teire.yml` opens **Configure Teire**. It adds only `.github/teire.yml` ([the defaults](/docs/guide/configuration#the-defaults)). Its body lists:

- what Teire found,
- the upgrades it will open after you merge, and what each means for your code,
- retired models in your code,
- API changes on operations you call,
- runtime notices,
- the inventory per ecosystem.

Merging it turns Teire on for the repository.
