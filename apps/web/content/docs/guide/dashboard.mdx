There are two dashboards. The web one at [/app](/app) covers every repository you can see. The **Teire Dashboard** issue lives inside each repository on GitHub. Both show the same findings, and both can start most actions: the issue adds Rebase, and the web adds Pause, Resume and Ignore.

## The web dashboard

Sign in with GitHub. When you sign in, Teire asks GitHub which installations you can see and shows only those repositories. If you install Teire somewhere new, sign out and in again so it shows up.

A repository page has five tabs:

| Tab | What it holds |
|---|---|
| **Findings** | Affected changes and those needing a person, each with **Fix now** or **Open PR #n**, and **Ignore**. Then the changes checked and ruled out, and the ignored ones with **Unignore** |
| **Inventory** | Every dependency with its version (or "unresolved"), scope and workspace |
| **Pull requests** | Teire's PRs, its "needs a human" issues and the onboarding PR, with their state |
| **Runs** | The latest 25 runs with their evidence and cost |
| **Config** | The resolved `teire.yml`: key, value, and whether it came from the repository, the organisation or the defaults |

### Buttons

**Rescan**, **Pause**, **Resume**, **Fix now**, **Ignore** and **Unignore** work like their [`@teire` commands](/docs/guide/commands). The page shows "Queued", then the result once the worker has done it.

The same rule applies as for a comment: you must have write access to the repository on GitHub. **Ignore** also closes that change's open PR.

## The Teire Dashboard issue

Once a repository is active, Teire keeps one issue named **Teire Dashboard** up to date. It is refreshed after every scan, every PR or issue Teire opens or updates, every ticked box, dashboard button and state-changing command.

| Section | Content | Tick the box to |
|---|---|---|
| Header | The last scan's commit and time, whether the repo is paused, a link to Teire | **Rescan now** |
| Upcoming deadlines | Each dated change, with its PR or verdict | |
| Affected | Each change with no PR yet: title, sites, priority | **Fix now** |
| Open PRs | Each Teire PR | **Rebase** |
| Needs a human | Links to Teire's issues | |
| Not affected, Not applicable | Collapsed lists with the reason for each | |
| Ignored | What you ignored | **Unignore** |
| Inventory | Dependencies per ecosystem | |
| Config problems | Keys that fell back to their defaults, and why | |
| Commands | The `@teire` command list | |

Ticking a box runs the action if you have write access. Teire then clears the ticks and comments `@you: …` with what started. Without write access nothing runs and the ticks are cleared. Set `dashboardIssue: false` in `teire.yml` to close the issue.
