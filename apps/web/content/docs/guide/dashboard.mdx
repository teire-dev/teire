There are two dashboards. The web one at [/app](/app) covers every repository you can see. The **Teire Dashboard** issue lives inside each repository on GitHub. Both show the same findings, and both can start most actions: the issue adds Rebase, and the web adds Pause, Resume, Ignore, the fix mode, Cancel and Retry.

## The web dashboard

Sign in with GitHub. When you sign in, Teire asks GitHub which installations you can see and shows only those repositories. If you install Teire somewhere new, choose **Refresh from GitHub** in the switcher or in Settings.

The sidebar holds the installation switcher (the account whose repositories you're looking at, and **Add an account on GitHub**), Overview, Repositories, Changes, Runs and Settings, and that installation's repositories. A blue dot marks a repository Teire is working on right now. Press <kbd>⌘K</kbd> (<kbd>Ctrl K</kbd>) to jump to a page or a repository, act on the repository you're on (each action asks once), or search these docs. Every list and every tab has its own address, so it can be linked and shared.

**Overview** shows a few rows per section and goes to the full list: Needs you (regressions, needs-a-human issues, drafts and stops from the last week), Open pull requests, Deadlines, Working now, Recent runs, and What Teire couldn't check (repositories whose last scan located calls by syntax rather than types, partial advisory data, or files it couldn't read).

**Repositories** filters by state (active, onboarding, paused, working), fix mode, open PRs, runs needing you, changes reaching code and language. Each row's fix mode changes in place; **Set fix mode…** applies one mode to every repository shown, each with its own result.

**Changes for you** lists each catalog change that reaches code in the installation, soonest deadline first, with the repositories it reaches. **Fix in all** first shows, for each repository, what Fix now would do there (start a run, a PR already open, or fixes off and where that is set), then sends one Fix now per repository that would start a run. Each needs your write access on that repository and gets its own result.

**Runs** lists every run, newest first, with the same filters the Overview's sections link to.

**Settings** has four sections: **Organization** (the installation's default fix mode, which only an organisation admin or the account's owner can change, and the organisation's `teire-config` defaults, changed through a config PR there), **Repositories** (each repository's fix mode), **Installations** (where Teire is installed, Refresh from GitHub, and changing repository access on GitHub) and **Usage**.

A repository page has seven tabs, each with its own address (`/app/repos/<owner>/<name>/<tab>`):

| Tab | What it holds |
|---|---|
| **Findings** | Changes reaching the code, each with its proof chain, **Fix now** or **Open PR #n**, and **Ignore ▾** (this version, major, minor or patch updates, or every update of the package); those decided in the sandbox (**Upgrade and check**); what the scan couldn't check; the changes checked and ruled out; and the ignored ones with **Unignore**. A link from Changes for you opens with its change first |
| **Pull requests** | Teire's PRs, its "needs a human" issues and the onboarding PR, each with its proof chain and state; an open PR has **Re-verify** and **Refresh**, a closed one **Recreate** |
| **Runs** | The latest runs with their proof chains and evidence |
| **Inventory** | Every dependency the last scan read, filtered by ecosystem and name, with its version (or "unresolved"), scope and workspace; long lists scroll without loading every row |
| **Providers** | The APIs and model providers the code calls, each with the changes from it that reach the code |
| **Config** | **Change a setting** (one `teire.yml` key and its value, sent as a pull request that keeps the file's comments and is checked against the schema), **Open starter config PR** when the file is missing or has problems, and every resolved key with whether it came from the repository, the organisation or the defaults |
| **Activity** | Every action on the repository, from this page, a comment or the Dashboard issue: who, what Teire answered, and the run or PR it produced |

Above the tabs, **Fixes** sets the repository's fix mode: **Automatic**, **Ask first** or **Off** (see [`fix-mode`](/docs/guide/commands)). It always shows the mode in force and where it was set. When `fixes:` in `.github/teire.yml` sets it, the control is locked and says so. Under Ask first and Off, the Findings tab lists **Upgrades available**: what Automatic would have started, each with **Upgrade** (Ask first) or none (Off).

### Buttons

**Rescan**, **Pause**, **Resume**, **Fix now**, **Ignore**, **Unignore** and the fix mode work like their [`@teire` commands](/docs/guide/commands). A message in the corner follows each one to what actually happened: "Rescan finished: 3 changes reach your code", "Refused: you need write access", or the run it started, with **Undo** where it can be undone (pause, ignore, a fix-mode change). A repository's **Activity** tab keeps every outcome.

The same rule applies as for a comment: Teire checks with GitHub, when it acts, that you have write access to the repository. **Ignore** also closes that change's open PR.

**Repositories** has **Set fix mode…** for every repository the list shows, with each repository's own result. **Settings** has each installation's default fix mode and whether security fixes start on their own; only an admin of the organisation (or the account's owner) can change them, and Teire checks that on GitHub.

A run page has **Cancel** while the run works: within seconds the model calls and the updater stop and its sandboxes are closed, and nothing is published after it. A cancel that arrives after the PR opened says it came too late. A failed or cancelled run has **Retry**.

A run whose PR is open has **Re-verify**: both sides run again on what the PR would merge, your own commits on its branch included, with its code unchanged. The after side is GitHub's test merge of the PR into the base branch as it is now, and the baseline is that base. A PR that conflicts with the base is checked as its branch stands, against the commit it branched from, and says so. Every project the PR's files touch runs its own checks; the weakest result decides. The result lands on the PR only if the PR is still open with the same head and base: a new **Teire** check run (failing for a regression), a comment, and the draft state and evidence label set to what the checks now show (a draft that verifies becomes ready; a ready PR that no longer verifies becomes a draft). Re-verify runs under every fix mode, since it changes no code; under Off it is how a PR marked `stale-evidence` gets current evidence, and the label comes off only when the merge with today's base was checked.

A run that ended in a "needs a human" issue has **Open draft anyway**: Teire opens its best diff as a draft PR titled **Unconfirmed**, labelled `unconfirmed` and with the evidence that stopped it, for you to finish by hand. It follows the fix mode and the PR limits as **Fix now** does, and it refuses, naming the file, when the diff holds a binary file or no longer applies.

**Share** copies the run's link and says who can open it: anyone, for a public repository; people with access to the installation, for a private one.

## The Teire Dashboard issue

Once a repository is active, Teire keeps one issue named **Teire Dashboard** up to date. It is refreshed after every scan, every PR or issue Teire opens or updates, every ticked box, dashboard button and state-changing command.

| Section | Content | Tick the box to |
|---|---|---|
| Header | The last scan's commit and time, whether the repo is paused, the fix mode in force and where it was set, a link to Teire | **Rescan now** |
| Upcoming deadlines | Each dated change, with its PR or verdict | |
| Affected | Each change with no PR yet: title, sites, priority | **Fix now** |
| Decided in the sandbox | Upgrades where some references could not be resolved, so the code alone doesn't settle them; the upgrade's run checks the repo before and after | **Upgrade and check** |
| Upgrades available | Under Ask first and Off: what Automatic would have started | **Upgrade** (Ask first) |
| Open PRs | Each Teire PR | **Rebase** |
| Needs a human | Links to Teire's issues | |
| Not affected, Not applicable | Collapsed lists with the reason for each; "not affected" only when every reference was resolved | |
| Ignored | What you ignored | **Unignore** |
| Inventory | Dependencies per ecosystem | |
| Config problems | Keys that fell back to their defaults, and why | |
| Commands | The `@teire` command list | |

Ticking a box runs the action if you have write access. Teire then clears the ticks and comments `@you: …` with what started. Without write access nothing runs and the ticks are cleared. Set `dashboardIssue: false` in `teire.yml` to close the issue.
